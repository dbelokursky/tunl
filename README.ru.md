**Tunl** — кроссплатформенный десктоп-клиент (macOS / Windows / Linux) для
VLESS, VMess, Trojan, Shadowsocks, Hysteria2 и WireGuard на JavaFX — оборачивает
[sing-box](https://github.com/SagerNet/sing-box) и даёт ему удобный GUI с живой
статистикой трафика, импортом share-ссылок, подписками, правилами маршрутизации
и иконкой в трее/меню-баре.

## Установка

### macOS

Сборки пока **не подписаны** сертификатом Apple Developer, поэтому при первом
запуске Gatekeeper заблокирует приложение. Разблокируется один раз через
системные настройки:

1. Откройте DMG и перетащите **Tunl** в папку **Программы** (Applications).
2. Запустите приложение. macOS сообщит, что не может проверить его на
   вредоносное ПО — нажмите **«Готово»** (Done), *не* «Переместить в Корзину».
3. Откройте **Системные настройки → Конфиденциальность и безопасность**
   (System Settings → Privacy & Security).
4. Прокрутите до раздела **«Безопасность»** (Security) — там будет сообщение
   «Приложение "Tunl" было заблокировано для защиты Mac».
5. Нажмите **«Все равно открыть»** (Open Anyway) и подтвердите паролем или
   Touch ID.
6. В появившемся диалоге нажмите **«Открыть»** (Open). Готово — дальше
   приложение запускается как обычно.

Нюансы:

- Процедуру придётся повторить после **каждого обновления** приложения — пока
  сборки не подписаны, macOS блокирует каждый новый бинарь заново.
- На macOS 13–14 есть путь короче: правый клик по приложению в Программах →
  **«Открыть»** → «Открыть». На macOS 15+ этот трюк для неподписанных
  приложений больше не работает — только через настройки.
- Эквивалент для терминала (снимает карантинный атрибут):

  ```bash
  xattr -d com.apple.quarantine "/Applications/Tunl.app"
  ```

Homebrew-tap пока нет, так что `brew install` Tunl не найдёт. Зато к каждому
релизу приложен готовый файл cask (`tunl.rb` с заполненными версией и
SHA-256) — для тех, кто хочет опубликовать его в собственном tap: из
отдельного файла Homebrew cask устанавливать отказывается. Подробнее —
[docs/DISTRIBUTION.md](docs/DISTRIBUTION.md).

### Windows

1. Запустите MSI. SmartScreen покажет «Система Windows защитила ваш
   компьютер» — нажмите **«Подробнее»** (More info) → **«Выполнить в любом
   случае»** (Run anyway).
2. Дальше обычный мастер установки. Приложение ставится per-user — права
   администратора не нужны.

Единственное, где Windows попросит повышение прав, — UAC-промпт при
подключении в режиме TUN.

### Linux (Debian/Ubuntu)

```bash
sudo apt install ./tunl_*.deb
```

Приложение ставится в `/opt/tunl` и появляется в меню приложений
(категория «Интернет»/Network).

Пакета в AUR пока нет. К каждому релизу приложены `PKGBUILD` и `.SRCINFO`
(на странице релиза он показан как `default.SRCINFO`), которые перепаковывают
`.deb` для Arch: скачайте `PKGBUILD` в пустой каталог и выполните
`makepkg -si` — или опубликуйте пакет сами; см.
[docs/DISTRIBUTION.md](docs/DISTRIBUTION.md).

### Переход с VLESS Client (1.4.x и старее)

В версии 1.5.0 приложение переименовано в Tunl. Серверы, подписки, правила
маршрутизации и сохранённые пароли переезжают сами — сменилось только имя
приложения, а не место хранения данных.

| ОС | Что происходит | Что сделать |
|---|---|---|
| Windows | MSI обновляет установленную версию на месте | ничего |
| macOS | `Tunl.app` встанет **рядом** со старым `VLESS Client.app` | удалить старое приложение, когда Tunl заработает |
| Linux | apt видит `tunl` как новый пакет, а не обновление | после установки — `sudo apt remove vless-client` |

## Первое подключение

1. **Добавьте сервер.** Вкладка **Серверы** → **Импорт ссылки** → вставьте
   ссылку `vless://…` / `vmess://…` / `trojan://…` / `ss://…` /
   `hysteria2://…` от вашего провайдера или целиком файл WireGuard `.conf` —
   форма заполнится сама. (Или **Добавить сервер** и заполните форму вручную;
   третий путь — вкладка **Подписки** с URL подписки, список серверов будет
   обновляться автоматически.) На свежей установке карточка на **Главной**
   сразу ведёт ссылкой в **Серверы**.
2. **Проверьте активный сервер** — клик по строке сервера вешает на него
   бейдж **АКТИВЕН**; именно он используется при подключении.
3. **Нажмите «Подключить»** на вкладке **Главная** (или `⌘⇧C` /
   `Ctrl+Shift+C`). Зелёный индикатор — подключено, оранжевый — подключается,
   красный — ошибка (смотрите вкладку **Логи**).
4. **Проверьте IP**: откройте [2ip.ru](https://2ip.ru) или выполните
   `curl ifconfig.me` — адрес должен смениться на адрес сервера.

### Какой режим выбрать

Выпадающий список **Режим** на Главной:

| | **Системный прокси** (по умолчанию) | **TUN** |
|---|---|---|
| Что идёт через туннель | приложения, уважающие системный прокси: браузеры, большинство CLI | **весь** трафик системы, включая то, что прокси игнорирует |
| Права | не нужны | нужны (см. ниже) |
| Когда выбирать | обычный сёрфинг | мессенджеры, игры, системные сервисы |

Рядом список **Сервер** решает, кто несёт трафик: **Выбранный сервер** — тот,
что с бейджем АКТИВЕН, — или **Самый быстрый**: ядро само замеряет все серверы,
переводит трафик на самый быстрый, а строка статуса называет сервер, который
оно на самом деле выбрало.

В обоих режимах собственные запросы Tunl — обновление подписок, проверка и
загрузка апдейтов, база стран — идут **через туннель**, пока он поднят, так что
они работают и в сети, где заблокированы нужные им сайты. (Если туннель поднят,
но не проходит проверку доступности, обновление подписки откладывается, а не
уходит в обход него.)

В режиме TUN туннель захватывает и IPv6 (**Настройки → Дополнительно →
Пропускать IPv6 через туннель**, включено по умолчанию); выключите, если у
сервера нет выхода в IPv6.

Что просит TUN на каждой ОС:

| ОС | Права для TUN |
|---|---|
| macOS | правило sudo-NOPASSWD (пароль один раз) или osascript-промпт на каждое подключение |
| Windows | UAC-промпт на каждое подключение |
| Linux | одноразовый `setcap` через PolicyKit (дальше без промптов) или pkexec-промпт при подключении |

## Как пользоваться

### Серверы

<p align="center">
  <img src="docs/screenshots/servers.png" width="900" alt="Список серверов с поиском, сортировкой и задержкой у каждого"/>
</p>

Поиск фильтрует сразу по имени, адресу, порту и протоколу. Сортировка — **Мой
порядок**, **По имени**, **По протоколу** или **Сначала быстрые**; **Замерить**
заполняет задержку для того, что сейчас показывает поиск. Пока туннель поднят,
замер идёт *через* прокси, а не до его адреса, — сервер, который отвечает, но
не работает, встаёт на своё место.

Клик по серверу делает его активным; Cmd/Shift-клик набирает выделение, а
удаление спрашивает один раз за всю пачку. Правый клик — **Редактировать**,
**Дублировать**, **Копировать ссылку** (недоступно для WireGuard: у него нет
формата share-ссылки), **Удалить**.

Сервер, чей TLS-сертификат никогда не проверяется (`allowInsecure` в ссылке
или в подписке), помечен янтарным бейджем **БЕЗ ПРОВЕРКИ СЕРТИФИКАТА**: любой
узел на сетевом пути может выдать себя за него.

**Бэкап** экспортирует все серверы в JSON-файл — учётные данные в нём в
открытом виде, храните его там, где прочитаете только вы, — и импортирует
обратно такой файл или простой список share-ссылок.

### Подписки

Вкладка **Подписки**: добавьте URL — список серверов подтянется и будет
пересинхронизироваться каждый час. **Изменить** правит имя или URL на месте
(серверы следуют за новым списком). В строке показаны только схема и хост URL,
потому что токен аккаунта живёт в его пути, а также квота провайдера, если
ответ пришёл с заголовком `subscription-userinfo` («использовано … из …»,
«истекает …»). Ссылки протоколов, которые Tunl не поддерживает (TUIC,
AnyTLS…), пропускаются, не помечая подписку как сломанную.

### Маршрутизация

<p align="center">
  <img src="docs/screenshots/routing.png" width="900" alt="Вкладка «Маршрутизация»: страны в обход, список исключений и свои правила"/>
</p>

Вкладка **Маршрутизация**, сверху вниз: **Страны в обход VPN** (их трафик идёт
напрямую; страны определяются по диапазонам IP, а ru, cn и ir — ещё и по
доменам), **Список исключений** (по одному хосту, шаблону, CIDR или IP в
строке) и **Свои правила**, которые сопоставляют по домену, суффиксу домена,
ключевому слову в домене, регулярному выражению, GeoSite, IP CIDR или GeoIP и
отправляют совпавшее **Через VPN**, **Напрямую** или **Блокировать**. Правило
«Блокировать» отклоняет соединение сразу (TCP reset, ICMP unreachable), а не
молча роняет его. В режиме TUN имена трафика, идущего напрямую, — список
исключений, правила «Напрямую», страны в обход — резолвятся через **DNS
прямой** из настроек, а не через туннель, так что резолвинг делится так же,
как и сам трафик.

### Мониторинг

**Главная** показывает живую статистику: скорость Upload/Download, суммарный
трафик. **Логи** — стрим логов sing-box с фильтром по уровню (сколько пишет
ядро — **Настройки → Уровень логов ядра**); кнопка **Скачать лог** сохраняет
лог ядра, а **Сохранить диагностику** пишет zip для отчёта об ошибке, в
котором учётные данные, URL, адреса серверов и SNI вырезаны — но всё равно
просмотрите его перед отправкой.

### Трей / меню-бар

Иконка даёт быстрые действия без открытия окна: **Показать окно**,
**Подключить**/**Отключить**, **Активный сервер**, **Выход**. Закрытие главного
окна (`⌘W`, красный кружок) **не** завершает приложение — оно живёт в трее;
выход — **Выход** в меню трея или `⌘Q`.

| ОС | Где |
|---|---|
| macOS | меню-бар |
| Windows | системный трей |
| Linux | там, где трей есть (KDE/XFCE/…); на стоковом GNOME трея нет — закрытие окна завершает приложение |

Цвет иконки отвечает на вопрос «доходит ли трафик наружу», а не «запустилось ли
ядро»: пока проверка сервисов не ответила, иконка остаётся жёлтой.

| Цвет | Значение |
|---|---|
| ⚪️ Серый | Отключено |
| 🟠 Жёлтый | Подключение, проверка или доступна лишь часть сервисов |
| 🟢 Зелёный | Подключено, и все проверяемые сервисы доступны |
| 🔴 Красный | Не удалось запустить или туннель поднят, но трафик не проходит |

Если проверка сервисов выключена, проверять нечего — подключённый туннель
просто зелёный.

Когда ядро неожиданно завершается, трей ещё и показывает системное
уведомление «Туннель остановлен»: туннель, упавший при скрытом окне, не
должен молчать.

### Обновление ядра sing-box

Ядро поставляется закреплённым внутри приложения и обновляется только вместе
с ним — отдельного обновления ядра нет. При запуске кэш, оставшийся от
прежнего пина, удаляется, так что всегда используется забандленный бинарь.

### Настройки

<p align="center">
  <img src="docs/screenshots/settings.png" width="900" alt="Настройки: внешний вид, соединение и проверка соединения"/>
</p>

Экран — колонка карточек. Текстовые поля сохраняются по Enter или когда вы
уходите из поля (пустое или недопустимое число оставляет прежнее значение);
всё остальное сохраняется сразу по клику.

| Карточка | Настройка | Описание |
|---|---|---|
| Внешний вид | Тема | Авто (как в системе) / Светлая / Тёмная |
| | Язык | Русский / English |
| Соединение | Автоподключение при запуске | Подключаться к активному серверу при старте |
| | Запускать при входе в систему | Стартовать вместе с ОС (см. [«Автостарт»](#автостарт)) |
| | Порт SOCKS / Порт HTTP | Локальные прокси-порты, по умолчанию `1080` и `1081`; оба слушают только `127.0.0.1` |
| | Уровень логов ядра | Сколько sing-box пишет во вкладку «Логи»: Отладка / Информация / Предупреждения / Ошибки; применится при следующем подключении |
| | Режим прокси | Системный прокси / TUN — тот же переключатель, что и **Режим** на Главной |
| | Автоматически настраивать системный прокси | В режиме системного прокси прописывать локальные порты в ОС при подключении и возвращать всё назад при отключении |
| Проверка соединения | Включить проверку соединения | После подключения проверять, что трафик действительно доходит до нескольких сервисов (включено по умолчанию) |
| | Авто-переподключение при недоступности | Переподключаться через задержку переподключения, если все проверки провалились |
| | Интервал проверки / Задержка переподключения | Секунды между проверками (`5`) и перед переподключением (`10`) |
| Дополнительно | DNS для прокси | Резолвер для имён, идущих через туннель; запросы уходят через туннель (`https://1.1.1.1/dns-query`) |
| | DNS прямой | Резолвер для имён, идущих напрямую: список исключений, правила «Напрямую», страны в обход (`https://223.5.5.5/dns-query`) |
| | Имя интерфейса TUN | `utun99` на macOS и Linux, `VlessClientTun` на Windows |
| | IPv4 адрес TUN | `172.19.0.1/30` |
| | Пропускать IPv6 через туннель | Включено по умолчанию; если выключить, в сетях с IPv6 такой трафик идёт мимо VPN |
| | Хранить учётные данные в системном хранилище | Запечатывать учётные данные серверов и URL подписок в Keychain / DPAPI / Secret Service вместо записи в JSON-файлы |
| Управление агентами (MCP) | Включить MCP-сервер, Порт, Разрешить изменения, Скопировать команду, Перевыпустить токен | См. [«Управление агентами»](#управление-агентами-mcp) |
| О программе | Версия Tunl, Версия sing-box, Проверить обновления | Строки версий заодно показывают статус обновления; **Перезапустить сейчас** появляется, когда обновление уже скачано. Здесь же — атрибуция DB-IP за флаги стран |

Настройки DNS и TUN действуют только в режиме TUN: в режиме системного прокси
у ядра нет секции DNS и, как и раньше, используется системный резолвер.

Где живут данные (`settings.json`, `servers.json`, `subscriptions.json`,
`routing.json`, кэш бинаря `bin/`):

| ОС | Путь |
|---|---|
| macOS | `~/Library/Application Support/VlessClient` |
| Windows | `%APPDATA%\VlessClient` |
| Linux | `~/.local/share/vless-client` |

В путях осталось старое имя приложения (до переименования оно называлось
«VLESS Client»). Так сделано намеренно: благодаря этому обновление находит
серверы, подписки и сохранённые пароли там же, где они лежали, — переносить
вручную ничего не нужно.

### Системный прокси по ОС

| ОС | Поведение |
|---|---|
| macOS | системные настройки прокси переключаются автоматически |
| Windows | автоматически (WinINET) |
| Linux | автоматически на GNOME; на других DE — прокси вручную (локальные порты работают везде) или TUN |

## Управление агентами (MCP)

Tunl умеет поднимать локальный **MCP-сервер** (Model Context Protocol), чтобы
ИИ-агенты — например, Claude Code — могли смотреть состояние и управлять
клиентом: статус, трафик, логи, список серверов, подключение/отключение,
добавление серверов из share-ссылок, правила маршрутизации и прочее.

### Безопасность

- Слушает только **`127.0.0.1`** (loopback) — из сети недостижим — и
  отвергает запросы, у которых заголовок `Host` или `Origin` не loopback
  (HTTP 403): это закрывает дверь DNS-rebinding-страницам, которые иначе
  добрались бы до порта через браузер.
- Каждому запросу нужен заголовок `Authorization: Bearer <token>`; токен лежит
  в файле `mcp-token` (в каталоге данных) с правами `0600`.
- **Выключен по умолчанию** — включается в Настройках.
- Изменяющие операции закрыты тумблером «Разрешить изменения» (включён по
  умолчанию). Самые опасные из них (подключение в режиме TUN, которое
  спрашивает пароль администратора macOS; удаление сервера) дополнительно
  требуют явного `confirm: true`.
- Каждый изменяющий вызов дописывается в `logs/mcp-audit.log`.
- В строках логов, отдаваемых агентам (`get_logs`, SSE-поток), URL урезаны до
  схемы и хоста, так что токен аккаунта из подписки этим путём наружу не
  уходит.

### Как включить

**Настройки → Управление агентами (MCP):**
1. Отметьте **Включить MCP-сервер** (порт по умолчанию `55555`).
2. При необходимости переключите **Разрешить изменения** (включено по
   умолчанию).
3. Нажмите **Скопировать команду** и выполните её:

```bash
claude mcp add --transport http tunl http://127.0.0.1:55555/mcp \
  --header "Authorization: Bearer <ваш-токен>"
```

**Перевыпустить токен** выдаёт новый токен и перезапускает сервер.

### Инструменты

| Категория | Инструменты |
|-----------|-------------|
| Чтение    | `get_status`, `get_traffic`, `list_servers`, `get_logs`, `list_subscriptions`, `get_routing`, `get_settings` |
| Действия  | `connect`, `disconnect`, `select_server`, `measure_latency`, `refresh_subscription` |
| Конфигурация | `add_server`, `update_server`, `delete_server`, `set_proxy_mode`, `set_setting`, `add_routing_rule`, `remove_routing_rule` |

Ресурсы для просмотра: `vless://status`, `vless://traffic`, `vless://servers`,
`vless://routing`, `vless://settings`, `vless://logs/recent`. Живой стрим логов
доступен по SSE (`GET /mcp`, `notifications/message`).

`get_status` возвращает состояние ядра в `state` / `connected`, а доступность
сервисов — в `health` и `tunnelStatus`. Поля `activeServerId` / `activeServer`
описывают сохранённый выбор; `currentServerId` / `currentServer` — последний
сервер, сообщённый ядром (null, пока он неизвестен или соединение отключено).

## Траблшутинг

**macOS: «Приложение заблокировано» / «Apple не может проверить»**
Это Gatekeeper и неподписанная сборка — пройдите
[шаги установки](#macos): Системные настройки → Конфиденциальность и
безопасность → «Все равно открыть».

**macOS: после обновления приложение снова заблокировано**
Так и будет, пока сборки не подписаны, — каждый новый бинарь проходит
Gatekeeper заново. Процедура та же.

**Кнопка «Подключить» недоступна**
Нет активного сервера — на вкладке **Серверы** нажмите на сервер, чтобы
появился бейдж **АКТИВЕН** (на свежей установке карточка на Главной ведёт
туда ссылкой).

**«Процесс неожиданно завершился (код N)»**
sing-box упал; трей показывает уведомление «Туннель остановлен». Причина — во
вкладке **Логи**. Частые: неверный UUID, неподходящий транспорт, недоступный
сервер, конфликт портов.

**TUN-режим запрашивает пароль каждый раз**
Создание TUN-интерфейса требует прав root/администратора: macOS показывает
osascript-промпт (или настройте sudo-NOPASSWD — тогда пароль спросят один
раз), Windows — UAC, Linux — pkexec (или одноразовый `setcap`).

**Порт 1080 или 1081 занят**
Ядро не стартует, во вкладке **Логи** — ошибка bind. Смените **Порт SOCKS** /
**Порт HTTP** в **Настройки → Соединение** на свободные.

**Linux: нет иконки в трее**
На стоковом GNOME трея нет (нужно расширение вроде AppIndicator), закрытие
окна завершает приложение. В KDE/XFCE трей работает из коробки.

**«sing-box binary not found» при запуске**
Актуально для запуска из исходников без бандлинга — см.
[раздел «Разработка»](#если-бандл-недоступен). В установщиках (DMG/MSI/DEB)
sing-box уже внутри.

## Разработка

### Быстрый старт

```bash
git clone https://github.com/dbelokursky/tunl.git
cd tunl
mvn clean javafx:run
```

При первой сборке Maven автоматически скачает `sing-box` (версия пиннится в
[singbox.properties](src/main/resources/singbox.properties)) под ОС и
архитектуру машины сборки в `target/classes/native/{os}-{arch}/` с проверкой
SHA-256. Бинарь бандлится в jar и извлекается при первом запуске. Бандлится
только архитектура хоста: jpackage собирает приложение под одну архитектуру,
так что DMG, собранный на Apple Silicon, всё равно не смог бы запустить
Intel-ядро.

### Если бандл недоступен

Если приложение запущено без build-time бандлинга (например, голый jar без
`generate-resources`), при старте появится модальный диалог, который скачает
`sing-box` с GitHub Releases и закэширует в
`~/Library/Application Support/VlessClient/bin/sing-box`. Загрузка защищена
проверкой SHA-256.

Если нет сети — в диалоге-установщике есть подсказка:

```bash
brew install sing-box
```

После ручной установки перезапустите приложение или нажмите **Retry
download** в оранжевом баннере на Главной — оно подхватит бинарь из
стандартных Homebrew-путей (`/opt/homebrew/bin`, `/usr/local/bin`) или из
`$PATH`.

### Требования

- JDK 25
- Maven 3.9+
- bash + curl + tar (стандартно для macOS) — нужны `generate-resources`,
  чтобы скачать sing-box

### Команды

```bash
mvn clean verify            # полная проверка: checkstyle, тесты, покрытие, SpotBugs
mvn clean javafx:run        # запуск в dev-режиме
mvn clean package           # сборка shade-jar (с бандлом sing-box)
mvn test                    # только тесты
mvn test -Dtest=SingBoxInstallerTest   # один тест-класс
mvn validate                # checkstyle

# перегенерировать docs/screenshots/*.png после изменения UI
mvn test -Dtest=ScreenshotGenerator -Dtunl.screenshots=true -Djacoco.skip=true
```

### Регенерация иконки

```bash
java --source 25 scripts/GenerateAppIcon.java
```

Генерирует PNG 16/32/64/128/256/512/1024 в `src/main/resources/icons/`.
Дизайн правится в [GenerateAppIcon.java](scripts/GenerateAppIcon.java).

### Обновление sing-box

Версия и SHA-256 живут в одном файле —
[singbox.properties](src/main/resources/singbox.properties). Его читают
pom.xml (properties-maven-plugin), [scripts/bundle-singbox.sh](scripts/bundle-singbox.sh)
и SingBoxInstaller, так что разъехаться они не могут. Бамп — одна команда:

```bash
scripts/bump-singbox.sh 1.13.14   # качает tarballs, сверяет SHA-256 с digest из GitHub API, обновляет properties
mvn clean verify -Psmoke          # полные тесты + smoke на реальном бинарнике
```

Smoke-профиль (`-Psmoke`,
[SingBoxRealBinarySmokeTest](src/test/java/com/vlessclient/service/SingBoxRealBinarySmokeTest.java))
прогоняет реальный бинарник: точное совпадение версии с пином,
`sing-box check` для всех протоколов × режимов × роутинг-пресетов и живой
`run` с проверкой clash_api и http-inbound. CI гоняет его на каждом PR и
перед сборкой установщиков.

Минорные обновления sing-box (1.13 → 1.14) ломают схему конфига — сначала
перенесите [SingBoxConfigGenerator.java](src/main/java/com/vlessclient/service/SingBoxConfigGenerator.java)
по [миграционному гайду](https://sing-box.sagernet.org/migration/), затем
поднимайте пин.

### Возможности (полный список)

- **Протоколы:** VLESS, VMess, Trojan, Shadowsocks, Hysteria2, WireGuard (через sing-box)
- **Транспорты:** TCP, WebSocket, gRPC, HTTP/2, HTTP Upgrade, QUIC
- **TLS / Reality / XTLS-Vision**
- **Режимы:** Системный прокси, TUN (IPv4 и IPv6)
- **Выбор сервера** — закреплённый сервер или самый быстрый из доступных (`urltest` в sing-box)
- **Подписки** — списки серверов по URL с ежечасным обновлением и квотой провайдера
- **Маршрутизация** — страны в обход, список исключений, свои правила по домену / суффиксу / ключевому слову / регулярному выражению / GeoSite / IP CIDR / GeoIP → Через VPN, Напрямую или Блокировать
- **Share-ссылки** — импорт `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`) и WireGuard `.conf`; экспорт всего, кроме WireGuard
- **Бэкап** — экспорт/импорт списка серверов
- **Латентность** — замер пинга до всех серверов одной кнопкой, через прокси, пока туннель поднят
- **Трафик** — живая статистика через Clash API
- **Диагностика** — архив с вырезанными секретами для отчётов об ошибках
- **Трей/меню-бар**, **хоткеи**, темы **Авто/светлая/тёмная**, **русский/английский**
- **Управление агентами** — loopback MCP-сервер для ИИ-агентов
- **Обновления** — встроенный апдейтер с проверкой SHA-256 и подписи Ed25519
